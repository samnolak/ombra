# ONI-01 — нативная проверка в Ombra

Сборка Release, macOS 26 (arm64), монитор 2560×1440 при 160 Гц, масштаб 200 %, если не сказано иное. Питомец 80 px
(уровень атласов 160).

## Что внедрено

- Логика эталона перенесена в C#: `src/Ombra.App/Pets/Oni/` — `OniSpec`, `OniDirector`, `OniPhysics`, `OniEffects`,
  `OniPet` (адаптер событий), `OniCarry` (перенос), `OniAtlases` (листы), `OniPainter` (порядок слоёв).
- Рендер: `Controls/OniView.cs`. Хит-тест только по телу (1,3h × 1,1h); поля под духов, знаки и пыль — отдельно
  (`OverflowFor`).
- Подключение: `PetsViewModel`, `PetStage`, `PetPerch`, `PetWindow`, страница настроек. Размеры ONI 64/80/96;
  32/48 не предлагаются.
- Старые пиксельные питомцы удалены вместе с кодом (`PetFrames`, `PetMoodMachine`, `PetLife`, `PetView`).
  Регрессии в остальных питомцах проверять поэтому не на чем.

## Чек-лист HANDOFF

| Пункт | Статус |
|---|---|
| Прозрачность и свечение, светлая и тёмная тема | проверено на нативных снимках; свечение запечено отдельно под каждую тему |
| Размеры 64/80/96 | проверено снимками; 32/48 исключены намеренно (HANDOFF: художественный минимум 64) |
| DPI 100/150/200 % | уровни атласов: 100 % — 64/96/96; 150 % — 96/128/160; 200 % — 128/160/192 (для 64/80/96). Снимок при 150 % проверен вручную |
| Смена монитора | **не проверено** вручную: второго монитора с другим масштабом не было. Код выбирает уровень заново при смене масштаба |
| Края окна без обрезки | `PetsTests` (зажим с учётом полей) |
| Каждый PetMood, временная и постоянная ошибка, отмена без радости, прерывания | `PetsTests` + parity |
| Drag из всех состояний, событие во время переноса, потеря захвата, click открывает чат ровно один раз | `PetsTests` (headless, ввод указателем); **вручную мышью не проверено** |
| Ввод и hover будят | `PetsTests` |
| Reduced motion, скрытие и возврат | `PetsTests`; при скрытии кадры не запрашиваются, при возврате dt ограничен |
| Освобождение текстур и таймеров | `OniAtlases`: листы общие, со счётчиком ссылок, освобождаются через 3 с после последнего пользователя (`IsFreed` в тестах) |

## Ресурсы и производительность

Листы декодируются один раз под уровень (кратный 32 px) и плотность экрана:

| Уровень | 64 | 96 | 128 | 160 | 192 | 256 |
|---|---|---|---|---|---|---|
| Память, МиБ | 5,5 | 12,3 | 20,7 | 28,9 | 39,0 | 63,3 |

Декодирование 127–200 мс, один раз.

| Состояние | CPU | Footprint |
|---|---|---|
| Без питомца | 0,05–0,09 % | 295 МБ |
| Без ограничения кадров (~160 fps) | 8,4 % | — |
| 30 fps, idle, окно на переднем плане | 4,6–5,4 % | 516 МБ, из них 147 МБ графики «unmapped» |
| 30 fps, на рабочем столе | 4,4 % | — |
| Работа omp, вместе с самим omp | 11,2 % | — |
| Без инвалидации окна (логика без кадров) | 0,85 % | — |
| Без рисования, с инвалидацией | 4,2 % | то же +130 МБ графики |
| Уснул, окно на переднем плане (~4 мин) | 0,0 % | 401 МБ, графика 16 МБ |
| Окно в фоне, ~4 мин | 0,0 % | 356 МБ |

- Рисование кадра 0,03 мс (в работе 0,15 мс), шаг логики меньше 0,01 мс. Почти вся цена — перерисовка окна
  в Avalonia.Native: без рисования CPU почти тот же. Отсюда ограничение: 30 fps, 90 в переносе, 15 после 120 с вопроса
  или ошибки, ноль во сне, в неактивном и скрытом окне и при reduced motion.
- Интервал кадров при ограничении 30 fps: среднее 38–40 мс, p95 ≈ 44 мс, т. е. ≈ 26 fps. Кадры выравниваются по
  обновлению экрана 160 Гц (6,25 мс), поэтому 33,3 мс округляется до 37,5–43,75 мс. Рывков нет: max 45 мс вне первых
  секунд (в первые 1–2 с после декодирования до 150 мс).
- Кэш Skia GPU: 10,5 МиБ из 28.
