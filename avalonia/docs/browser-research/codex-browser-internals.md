## Takeaways for the Avalonia/.NET browser [INFERENCE]
1. Device mode in Codex is viewport-size + visual scale only (DPR 1, `mobile:false`, no touch/UA). Real mobile emulation (UA, touch, DPR) needs our own work; on WebView2 CDP `Emulation.setDeviceMetricsOverride{mobile:true,deviceScaleFactor}` + `setTouchEmulationEnabled` + `setUserAgentOverride` are available; WKWebView only `customUserAgent` + frame size.
2. Copy: full-size webview + `scale` transform; symmetric ×2 horizontal drag; 240×160..4096 clamps; rotate-keeps-preset rule.
3. Agent input must be trusted native events (CDP Input / platform events), page focus emulated, cursor waits for arrival; background agent tabs kept painting (opacity 0.001 parking, no throttling).
4. Native dialogs/auth/file chooser are runtime-native in Codex; with WebView2/WKWebView/WebKitGTK we must wire each callback ourselves. `window.open` with features should keep the opener (Codex loses it for `new-window`).
