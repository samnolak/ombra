## Notes

- **PARITY.md устарел относительно закреплённого omp 18.8.0.** В RPC уже есть `fork`, `get_tree`, `btw`/`btw_cancel`/`get_btw_history`, `goal`, `cancel_subagent`, `steer_subagent`, `abort_and_restore_queue`, `promote_queued_message`, `set_cache_warming`, `set_event_filter`, `predict_word`, `open_session`, `set_ask_dialog`, `set_slow_mode`, `get_entries` (rpc-types.ts:40-145). PARITY §3/§5 всё ещё ведёт `/fork`, `/tree`, `/btw`, `/goal` в терминал. Строка `get_messages, get_messages_page` = Done неверна: используется только `get_messages`.
- **Запросы в upstream omp** (оформить как предложения; omp не форкаем и не патчим):
  1. RPC для plan mode (enter/exit, событие с документом плана, approve/reject + feedback).
  2. Файловые чекпоинты по ходам или хотя бы событие «файл изменён» с путём — иначе GUI делает это сам через git snapshot.
  3. RPC отмены и просмотра вывода background jobs.
  4. Входящий `rpc_chunk` (клиент→omp), чтобы снять лимит строки в 1 MiB: из-за него у нас 3 картинки по 230 KB.
  5. MCP form-elicitation через `extension_ui_request`.
- **Риск P1 (slash во время хода)** проявляется уже сейчас. Самые частые реальные случаи: `/compact` или `/rename`, набранные пока агент работает, уходят модели текстом, тратят ход и путают её.
- **Оптимизация `set_event_filter delta`** дешёвая (одна команда после negotiate) и даёт линейный трафик. Особенно важно для нескольких одновременных чатов и длинных ответов с thinking.
- Hooks и output styles Claude в omp реализованы extensions/rules: это omp-core, отдельной GUI-поверхности не требуют. Из этого класса для GUI полезно одно — показывать источник (extension) в карточке разрешения, когда запрос пришёл от extension (Claude 2.1.75), если omp передаёт источник ([INFERENCE], не проверено).
- Статусы по Background tasks, Approvals и Session частично собраны scout-агентами и выборочно перепроверены вручную: TasksViewModel (stop нет), rewind (метки и картинки), SubmitAsync/QueueAsync + omp followUp, get_messages, set_event_filter, ImageAttachments, App.axaml.cs.
