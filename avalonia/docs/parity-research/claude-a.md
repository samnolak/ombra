## Notes

- **Неточность документации:** `avalonia/docs/PARITY.md:230` утверждает, что `get_messages_page` используется («Done — history when a session opens»), но код использует только `get_messages` (`SessionController.cs:151`; grep `messages_page` находит только комментарий в `OmpCommands.cs:148`). Исправить вместе с B2.
- **Запросы к omp (upstream):**
  1. Входящий `rpc_chunk` от клиента — снимет лимит 3 картинки × 230 KB.
  2. RPC для отмены отдельного субагента или job и для «перевести в фон».
  3. MCP OAuth и URL elicitation по RPC.
  4. Plan mode и `plan_review` по RPC.
  5. Стабильные `timestamp` и id у всех ролей сообщений в `get_messages_page`, чтобы гидрация воспроизводила живой вид (B3).
  6. Поле превью вариантов у `ask`.
- **Риски безопасности в порядке важности:**
  1. B4 — случайное одобрение цифрой без задержки.
  2. Браузер агента действует на залогиненных сайтах без согласия по сайту (cookies превью хранятся).
  3. Невидимый Unicode в промпте и в тексте страниц, которые уходят агенту.
  4. Скрытый URL ссылок.
- **Что у нас уже лучше, чем было у Claude до их фиксов:** очередь approvals «1 of N» с самыми старыми впереди; Stop отменяет ожидающие approvals; инкрементальный рендер Markdown с ограничением глубины; кадр протокола ограничен 1 MiB; корректная обработка U+2028; graceful stop через stdin EOF и handle-based kill дерева; ответ на устаревший запрос не уходит; поле approval-режима показывает отложенный режим.
- Не вошло в отчёт: vim-режим, OSC-специфика терминала, screen-reader-фиксы TUI, Remote Control, artifacts, ultrareview, Claude in Chrome extension, auto-mode classifier и биллинг — либо N/A, либо агентное поведение omp без отдельной поверхности в GUI.
