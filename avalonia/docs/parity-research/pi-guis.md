# Другие GUI-клиенты pi/omp: оптимизации и функции, которые стоит перенять

Что изучено. Клоны лежат в `/tmp/guis/<name>`, история: pi-gui 902 коммита, orbit 175, PiPilot 148, piggy 131, pi-heao-gui 193, PIDesktop 32, pi-desktop 11.
- **pi-gui** (minghinmatthewlam, Electron)
- **piggy** (wxk6b1203, Tauri+Rust)
- **pi-desktop** (Inas1234, Tauri)
- **pi-heao-gui** (Q1y1ng, Electron)
- **PIDesktop** (Llllviaaaa, Tauri)
- **PiPilot** (GarlandQian, Electron)
- **Orbit** (imrj05/orbit, Rust+GPUI)

Наш код проверен grep/read; в каждой строке указаны файл и символ. Ничего не собиралось и не запускалось.

**Итог в одной фразе.** Самые дорогие проблемы чужих клиентов у нас уже решены, и решены лучше:
- покадровое объединение стрима;
- инкрементальный Markdown;
- виртуализация с запоминанием высот;
- backpressure;
- reaper сирот.

Реальные пробелы — в I/O вокруг сессий (каталог, открытие, внешние изменения), в Windows-жизненном цикле процессов и в защите сессии от двух писателей.

## Notes

- **Где мы сильнее.** Наш RPC-слой (`RpcConnection`: `PipeReader`, bounded channel с backpressure вместо отбрасывания, v2 reassembly, корреляция и timeout с очисткой `_pending`, unmatched responses как события) аккуратнее, чем у всех семи клиентов:
  - у Orbit — 3 потока + `read_until`;
  - у PiPilot — дефолтные Node streams.

  Reaper сирот на macOS/Linux (`OwnedProcesses` с маркой `OMBRA_OWNER`) вообще нет ни у кого. Обработка нетерминального `agent_end` через get_state-probe (SessionController.cs:889-957) соответствует правилу pi-desktop «idle только по `agent_settled`».
- **Не переносить:**
  - Orbit `rpc_patches.rs` (патчит бандл pi) — нарушает наше правило «never patch omp».
  - Orbit guard-extension через `--extension` — у нас approval modes и `ApprovalRules` поверх штатного RPC.
  - Typewriter-сглаживание PiPilot (rAF + 28 мс) — косметика, отрисовка раз в кадр у нас уже есть.
- **Upstream-просьбы к omp:**
  1. Нативный lock или lease файла сессии (иначе GUI и CLI/TUI на одном файле портят дерево).
  2. Нужно убедиться, что omp при перечислении сессий игнорирует `*.jsonl.lease` (pi — да, `endsWith(".jsonl")`, по pi-gui 4d14712; для omp — [INFERENCE]).
  3. Стабильный id записи на live-строках ассистента. pi-gui добавлял его скрытым extension `transcript-identity.ts`; у нас ключ строки локальный (`TranscriptItem.Key`), поэтому после reload совпадения строк нет.
- **Риск spare + несколько чатов при старте:** до 4 omp + spare могут стартовать одновременно. Если omp 18.8 ставит пакеты при старте, возможна гонка, как у pi-heao (см. строку про spawn-queue) — проверить.
- **Порядок работ** (наибольший эффект при наименьшем объёме):
  1. Кэш каталога.
  2. Job Object.
  3. Lease.
  4. Focus-reconcile.
  5. Мгновенный первый кадр + пейджинг.
  6. Решение по spare и hibernate на основе замеров.
